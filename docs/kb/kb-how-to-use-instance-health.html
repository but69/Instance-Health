What Instance Health does

Instance Health adds 73 checks to Instance Scan. They look for configuration and code that slows the instance down, exposes data, makes upgrades harder or leaves records in a poor state. All checks are grouped in the scan suite Instance health.

After every scan of the suite, the app turns the findings into one health score from 0 to 100 (100 = completely healthy) and stores it, so you can follow the trend over time.

One number per scan
The health score, plus sub-scores for security, performance, manageability and upgradability.
Findings you can act on
Each finding links to the record you have to change, for example the report, script or ACL.
Trend instead of snapshot
Every scan adds a point to the trend chart, so you see whether cleanup work pays off.

Where to find it

Open the application menu Instance Health in the navigator. It is visible for users with the role admin.

ModuleWhat it shows
DashboardTrend chart of the health score and all scores per scan result in a list. Start here.
Health ScoresOne record per scan: health score, sub-scores, number of findings, knock-out checks and checks that failed.

The findings themselves are in Instance Scan (Instance Scan > Findings).

Run a scan

1
Start the suite

Open BiHa-Instance Health > Health Scores and click the banner button BiHa-Run Instance Health Scan. The button starts the suite “Instance health” with all checks. If a run of the suite is still in progress, you get a message instead and no second run is started.

2
Wait for the scan to finish

The scan runs in the background; follow it in Instance Scan > Scan Results. A run takes about 15 minutes, depending on the size of the instance.

3
Wait for the health score

A scheduled job “BiHa-Instance Health - calculate health score” runs every minute and calculates the score of every finished run that has none yet. The new record then appears in the list and on the dashboard.

Note: The app does not start scans by itself. Run the scan regularly (for example after each release or upgrade), otherwise the trend has no new points.

Read the dashboard

The dashboard Instance Health has three parts:

  • Filter “Trend lines” (top): choose which lines the chart shows: the overall health score, security, performance, manageability, upgradability. Without a selection all five are shown.
  • Trend chart: the average score per scan date, one line per selected trend line. The chart is for reading only; clicking a point does nothing.
  • Score list (below the chart): one row per scan result, newest first, with scan date, health score, findings, checks evaluated, checks failed, knock-out and the manageability score. It follows the filter.
Tip: A drop between two scans means new findings. Compare the findings of the two scan results in Instance Scan to see what changed.

Work through the findings

1
Start with the priority 1 checks

Priority 1 checks have the largest impact on the instance and on the score (see below). Fix these first, especially a check with a knock-out: it caps the whole health score at 60.

2
Open the finding

The finding shows what is wrong in the details (for code checks the matching lines) and links to the record that has to be changed. The check itself holds the resolution details: what to do about it.

3
Fix, or accept the finding

Fix the record, or decide that the finding is acceptable and note the reason. The next scan reports whatever is still open.

4
Scan again

Run the scan again and check that the finding is gone and the health score went up.

Which checks exist, what they find and why they matter is described in the article Instance Health: all scan checks.

Note: Code checks only report custom records (your own scoped apps and customized global records). Code delivered by ServiceNow is not reported.

Questions and answers

I ran the scan but there is no new health score. Why?
The score is calculated by a job that runs every minute, and only for finished runs of the suite. Wait for the scan to finish and for the next job run. Check that the job “BiHa-Instance Health - calculate health score” is active.
The score is 60 although there are only a few findings. Why?
A priority 1 check scored 0 and triggered the knock-out cap. The list shows the knock-out checks of the scan. Fix them first; the uncapped score is kept on the record.
A check is missing from the score of a scan.
Checks that did not run or failed in the scan are not counted. They are listed in the field “checks failed” of the health score record.
Why does a check report so many findings that I cannot fix them?
The score of a check drops by a fixed number of points per finding, down to 0. More findings than that do not make the score worse, so you can work through them step by step and see the score rise once the count falls.

How the health score is calculated

The health score is built in three steps: a score for every check, a weighted average of all checks, and a cap when a critical check fails. 100 means completely healthy.

1. Score per check (0 to 100)

Every check starts at 100. Each finding deducts points, depending on the priority of the check. The score never goes below 0.

PriorityMeaningPoints per findingScore is 0 afterWeight
1Largest impact: instance-wide or all users, data exposure, breaks upgrades205 findings5
2Noticeable impact on single processes, users or areas520 findings3
3Data quality, housekeeping, maintainability250 findings1

Setting checks: some checks look at one setting or limit (for example impersonation in production, call stack logging, rows per page). One finding means the setting is wrong, so the check scores 0 with the first finding.

Share checks: two checks measure a share instead of counting findings. “Unique location names” scores the share of unique names; “CIs not discovered or updated for 60 days” scores 100 minus the share of stale CIs.

2. Health score: weighted average

The health score is the average of all check scores, weighted by priority (5 for priority 1, 3 for priority 2, 1 for priority 3). A priority 1 check therefore counts five times as much as a priority 3 check.

3. Knock-out cap at 60

If a priority 1 check scores 0, the health score is at most 60, however good the rest is. A single critical problem, such as a public report or a table without ACLs, must not disappear in the average. The value without the cap is kept in the field score uncapped.

Sub-scores

The same calculation is made per priority and per category: security, performance, manageability and upgradability. They show where the weak spots are.

Example

CheckPriorityFindingsCheck scoreWeight
Global UI scripts12100 − 2 × 20 = 605
Roles assigned directly to users28100 − 8 × 5 = 603
Update sets without description310100 − 10 × 2 = 801

Weighted average: (60 × 5 + 60 × 3 + 80 × 1) / (5 + 3 + 1) = 560 / 9 = 62.2. No priority 1 check is at 0, so there is no cap. If the global UI scripts had 5 findings, that check would be at 0, and the score would be at most 60.

What is not counted

  • Checks that did not run or failed in the scan (the platform would give them 100). They are listed in “checks failed”.
  • Records in tables that ServiceNow generates itself (for example Generative AI Framework scheduled scripts), which are never treated as custom.
Note: Instance Scan shows its own score per check, using the same points per finding. The overall health score and the knock-out cap exist only in this app.
