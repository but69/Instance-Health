How to read this list

The checks are grouped by topic. The column P is the priority, which sets how much a finding costs in the health score (see the article How to use Instance Health):

  • P1 largest impact: instance-wide or all users, data exposure without login or ACL, breaks upgrades. 13 checks.
  • P2 noticeable impact on single processes, users or areas. 31 checks.
  • P3 data quality, housekeeping, maintainability. 29 checks.
Note: Checks on code (scripts, business rules, client scripts, UI actions and similar) report custom records only. Code delivered by ServiceNow is not reported. Retired CIs are left out of the CI checks.

Security and access

Who can see or do what: public content, missing ACLs, roles, users and open endpoints.

IH-0171Tables without ACLsTables that have no record ACL, neither their own nor one inherited from a parent table.Without ACLs, access to the table is not controlled by the platform’s rules.

IH-0642Active user accounts without loginActive users whose last login is older than 90 days, or who never logged in and were created more than 90 days ago.Unused accounts with roles are an attack surface and cost licenses.

What the checks do not cover

  • ServiceNow’s own code: code checks report custom records only.
  • Records that ServiceNow generates itself (for example Generative AI Framework scripts) are never treated as custom.
  • Checks that cannot run in the app scope: the skipped items of an upgrade are summarized in one finding (IH-021), and the priority of skipped items is not checked.

The resolution for each check is written in the check itself (field Resolution details in Instance Scan) and on every finding.
